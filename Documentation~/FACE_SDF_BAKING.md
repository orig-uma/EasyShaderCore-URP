# 顔 SDF ベイク手法仕様 — 距離場ブレンド + 16bit パッキング

ジオメトリだけから（外部ツール・手描き無しで）lilToon 互換の顔 SDF シャドウ
テクスチャを焼く手法の完全仕様。**この文書単体で再実装できる**ことを目標に、
式・規約・落とし穴をすべて規範（MUST / MUST NOT）で書く。

実装: `Editor/Baking/EasyPbrFaceSdfBaker.cs`（パイプライン共通部は
`EasyPbrBakeCore.RunBake`）。T-346 / T-354 / T-355 / T-357。

## 0. 先行手法との関係（正直な位置付け）

「白黒影マスク → 距離場変換 → ブレンド」で滑らかな SDF を作る発想自体は
既知の手法（alwei 方式。rid_316 氏の note 記事が 16bit 化まで含めて公開している）。
本手法の寄与は次の 4 点で、**発明ではなく既知手法の自動化と数値工学**:

1. **マスクスタックを焼かない定式化** — 頂点スイープの連続な閾値マップを
   1 回ラスタライズし、等値線を画像空間で切り出す（§3）。N 枚のマスク描画が不要
2. **適応ランプ幅による連続再構成**（§3.4）— 固定幅だと出力が量子化される
   問題の解。この一点が 16bit 出力を意味あるものにする
3. **遮蔽レイのサブメッシュ限定**（§2.3）— 統合メッシュで成立させるための必須条件
4. **RG 16bit の線形性を使ったパイプライン設計**（§5）— バイリニア・ブラーを
   通しても値が壊れない順序の規定

## 1. 出力の規約（最重要 — ここを間違えると全部が無駄になる）

### 1.1 値の意味（角度写像）

テクセルの値 `sdf` は「その点が陰に落ちるライト方位角の閾値」を表す:

```
ライト方位角 φ:  0 = 顔の正面から, π = 真後ろから（水平面内）
ランタイムの閾値: threshold(φ) = 1 − (cos φ · 0.5 + 0.5)     … φ=0 → 0, φ=π → 1
点が照らされる条件: sdf > threshold(φ)
```

したがって **白（1.0）= 最後まで照らされる側 / 黒（0.0）= 正面光でも陰**。
これは lilToon 系の 1ch SDF テクスチャと同じ規約。

**検算アンカー（実装後に必ず 2 点確認すること）**:
- どの角度でも照らされ続ける頂点（例: 頬の最も張った点）→ 格納値 ≈ 1.0（白）
- 正面光ですでに陰の頂点（例: 深い眼窩・顎の裏）→ 格納値 ≈ 0.0（黒）

**内部計算は逆向き**である点に注意（§2.4）。内部では
`f = cos(遷移角)·0.5 + 0.5`（白 = すぐ陰る側）で持ち、**パッキング時に
`1 − f` へ反転する**（§5.1）。反転を忘れると「すぐ陰るはずの顎下〜首が
永遠に照らされる」誤読になる（実際に出荷した不具合。T-354）。

### 1.2 チャンネルと精度

**16bit 1ch モード**（lilToon 互換・推奨）:

```
u16   = round(clamp01(1 − f) × 65535)
R8    = u16 >> 8        （上位バイト）
G8    = u16 & 0xFF      （下位バイト）
B8    = 0,  A8 = 255
デコード（HLSL）: sdf = dot(tex.rg, float2(65280.0, 255.0)) / 65535.0
```

デコードが R・G に**線形**なので、バイリニア補間・（float 域での）ブラーを
通しても値が壊れない。8bit 単チャンネルは閾値が約 0.7 度刻みの階段になり、
ライトを回すと影の線がカクつく — 16bit はその対策。

**4ch モード**（左右非対称の顔向け・8bit）: R/G/B/A = 右/左/上/下光の閾値。
こちらは**反転しない**（内部規約のまま格納。読む側が対で異なるため）。

### 1.3 テクスチャアセット設定（MUST）

- **sRGB OFF**（Linear）
- **非圧縮**（BC 圧縮は R と G の相関を壊し、16bit デコードが破綻する）
- ミップマップは任意（デコードが線形なのでミップも正しく平均される）

## 2. 段 1: 頂点スイープ（閾値マップの素材）

メッシュの各頂点について、ライトを正面から真後ろへ掃引し、
「照らされている → 陰」に切り替わる角度を求める。

### 2.1 ライトベクトルの掃引

```
fwd  = 顔の正面（Transform.forward。-Z 向きモデルは反転オプション）
axis = 掃引先の軸（右光なら Transform.right）
tilt = X Axis Tilt（度）: axis を顔の up 方向へ tilt 度倒して正規化
       （左右どちらの軸も同じ「上」へ倒す＝左右対称が保たれる。
         顎下〜首の境界を「やや上から差す光」前提に合わせる補正）

θ を 0 → π で steps 分割（既定 90）:
    L(θ) = normalize(fwd · cos θ + axis · sin θ)
```

### 2.2 照射判定

```
lit(θ) = dot(N, L(θ)) > ndotlThreshold          … N = 位置溶接した頂点法線（ワールド）
```

**法線は位置で溶接してから使うこと（MUST — T-372 の事故）。** ミラーで作られた
顔は中央線の頂点が左右で分割されていることが多く、法線が中央で不連続になる。
そのまま掃引すると遷移角がジャンプし、UV 中央に縦一直線の段差が焼き込まれる
（実測: 4 テクセルで 0.05〜0.16 ＝ 周囲の勾配の 30〜50 倍）。光が 80〜90 度の
とき、その段が額から顎までの硬い割線として絵に出る。量子化位置（1e-5 m）で
同一点とみなした頂点の法線を平均してから N に使う。UV 継ぎ目・硬エッジの
分割も同じ理由で溶ける。

さらに落ち影を含める場合（Cast Shadow ON）:

```
lit(θ) &= !Raycast(頂点位置 + N·1e-3, L(θ), castDistance)
```

### 2.3 遮蔽コライダーの限定（MUST — T-355 の事故）

レイキャストの遮蔽コライダーは**対象マテリアルのサブメッシュだけ**から
構築すること。統合メッシュ（VRM 等）は 1 つの Mesh に睫毛・眉など
**別マテリアルの浮きジオメトリ**が同居しており、メッシュ全体を遮蔽物に
すると顔の頂点からのレイがそれらに当たり、「正面からでも陰」＝恒久影
（値 0 のブロブ）が目の周りに焼き込まれる。鼻・唇の落ち影は同マテリアル
なので、限定しても正しく残る。

### 2.4 遷移角の記録（内部規約）

```
f = 1.0                            … θ=0 で既に陰（正面光でも陰）
f = cos(θt)·0.5 + 0.5              … lit→!lit の最初の遷移角 θt で決定
f = 0.0                            … 最後まで lit（π まで照らされ続ける）
```

**内部は「白 = すぐ陰る側」**。§5.1 の反転を経て出力規約（§1.1）になる。

頂点値はラプラシアン平滑化（隣接頂点平均・既定 1 回）を掛けてよい。
**ただし位置溶接したグラフの上で行うこと（MUST — T-373 の事故）。** Unity は
UV 継ぎ目で頂点を複製する。素の三角形隣接で平均すると、継ぎ目の左のコピーは
左側の隣接とだけ・右のコピーは右側の隣接とだけ平均され、同じ点だった値が
**勾配 × 平滑化回数ぶん割れる**（実測: 額 0.05 / 鼻 0.16）。法線が連続でも
起きる ── 溶接は入力だけでなく途中の全段に要る。

## 3. 段 2–3: ラスタライズと距離場ブレンド（本手法の核）

### 3.1 ラスタライズ

頂点値 f を UV 空間へ重心座標補間でラスタライズする（解像度 res、既定 1024）。
**書き込みは対象マテリアルのサブメッシュのみ**。書いたテクセルを
coverage マスクとして持つ。

この生の出力は「頂点法線 → 重心補間」なので、影境界の等値線に
ポリゴン割りと法線ノイズがそのまま出る（線がガタつく）。次段で直す。

### 3.2 なぜ距離場ブレンドか

手描き SDF ツールの本質工程は「2 値マスク → 距離場変換 → ブレンド」。
等値線の形を**テクセル距離の幾何**で決め直すことで、頂点補間由来の
ガタつきが丸まる。ここでは N 枚のマスクを別々に焼く代わりに、
連続場 f の等値線を画像空間で切り出して同じ結果を得る。

### 3.3 等値線ごとの符号付き距離

```
K = 64（等値線の本数。出力は 1/K に量子化されない — §3.4 の適応幅による）
各 k = 0..K−1 について θk = (k + 0.5) / K:

  inside(t) = coverage(t) && f(t) ≥ θk        … 被覆外は種にしない
                                                （UV アイランドの外から
                                                  等値線が引っ張られない）
  dOut = chamfer距離変換( 種 = inside のテクセル )      … 外側での「内側までの距離」
  dIn  = chamfer距離変換( 種 = coverage && !inside )    … 内側での「外側までの距離」
  sd_k(t) = clamp(dIn − dOut, −res, +res)               … 内側 +・外側 −
```

chamfer は 2 パス（3-4 近似: 直交 1.0 / 斜め √2）。種が片側に無い等値線
（全面が内側 or 外側）は距離が Inf になるので ±res へ丸める —
ランプ幅 ≤ res のため §3.4 の式がちょうど 1 / 0 に飽和して正しい値になる。

### 3.4 適応ランプ幅による再構成（MUST NOT: 固定幅）

```
w_k(t) = max(spread, 0.5 · (sd_{k−1}(t) − sd_{k+1}(t)))   … 局所の等値線間隔
                                                            （端の k は自身で代用）
f'(t)  = (1/K) · Σ_k clamp01(0.5 + sd_k(t) / (2 · w_k(t)))
```

- **ランプ幅を spread 固定にしてはならない。** 等値線同士が spread より
  離れた平坦部で全ランプが 0/1 に飽和し、出力が 1/K 刻みに量子化される
  （段々畑。ライトを回すと影の線が等値線ごとに引っかかり、16bit が無意味になる。
  実際に出荷して「元の方がよかった」評価を受けた欠陥。T-346 初版）
- 幅を局所間隔まで広げると、隣接ランプがちょうど連結する**区分線形の連続
  再構成**になり、平坦部は元の値が保存される
- `spread`（Line Softness。既定 4 texel）は**線の形を丸める半径の下限**として
  だけ効く。上げるほど滑らか・細部が消える（8〜12 が実用域）

マスクは入れ子（θ が上がると内側が縮む）なので sd_k は k について単調減少
＝ 間隔の式は非負（数値ノイズは max の spread 下限が吸収）。

メモリは sd の 3 レベル分（k−1 / k / k+1）のリングで足りる。
計算量は K × 2 距離変換 × res² — 1024px・4ch で十数秒（CPU）。

### 3.5 ダイレート不要

距離伝播が被覆外テクセルにも自然な外挿値を入れるため、UV 継ぎ目の
ダイレート処理は不要になる（従来パイプラインのダイレート段は 0 でよい）。

## 4. 段 4: ブラー（順序が規範）

ブラーを掛ける場合は**16bit パッキングの前に float 域で**掛けること（MUST）。
パッキング後に 8bit チャンネル別でブラーすると、上位バイト R の丸め誤差
（±0.5/255 ≈ 16bit の ±128 相当）で実効精度が 8bit 未満に落ちる。
分離ボックス（横→縦）で十分。距離場ブレンド後は全テクセルに有効値が
あるので被覆判定は不要。

## 5. 段 5: パッキングと保存

### 5.1 反転（MUST — T-354 の事故）

内部値 f（白 = すぐ陰る）を `1 − f` に反転してから §1.2 の式で RG へ詰める。
理由と症状は §1.1 の検算アンカー参照。

### 5.2 掃引方向とミラー U

16bit 1ch は**右光の掃引だけ**を焼く。左からの光はランタイムが U を
ミラーして読む（lilToon と同じ規約）— **左右対称の顔 UV が前提**。
左右非対称（傷・模様）は 4ch モードを使う。

## 6. ランタイム消費（参考: Idol 1ch 経路 / lilToon）

```hlsl
float2 rg  = SAMPLE(_FaceSDFMap, uv or mirrored-uv).rg;
float  sdf = dot(rg, float2(65280.0, 255.0)) / 65535.0;
float  FdotL = dot(顔正面のXZ正規化, ライトのXZ正規化);
float  threshold = 1.0 - (FdotL * 0.5 + 0.5) + offset;
float  lit = smoothstep(threshold - soft, threshold + soft, sdf);
// U ミラー: dot(顔右方向, ライト) < 0 のとき u → 1−u
```

lilToon で使う場合はベイクした PNG をそのまま影マスク（SDF）スロットへ。
非圧縮・sRGB OFF の設定だけ確認すること（§1.3）。
※ lilToon 側が 16bit RG デコードを持たない版では R 単独（8bit 精度）として
読まれる — 線の形の品質（距離場ブレンドの効果）はそのまま得られる。

## 7. 再現実装のための検証チェックリスト

実装したら上から順に。**1 つでも飛ばすと過去に出荷した不具合を再現する。**

1. **規約の 2 点検算**（§1.1）: 常時照射の頂点 → 白 / 正面から陰の頂点 → 黒。
   逆なら §5.1 の反転漏れ（症状: 顎〜首に影が入らない）
2. **平坦部の量子化検査**: 頬など平坦な領域のデコード値のヒストグラムを取り、
   1/K（=1/64）間隔のピークに集中していないこと。していれば §3.4 の
   適応幅が入っていない（症状: ライト回転で影の線がカクつく）
3. **焼いた PNG の目視**: 目の周りに黒いブロブ（値 0 の領域）が無いこと。
   あれば §2.3 の遮蔽限定漏れ（症状: 目の周りに恒久影）。
   また **UV 中央の縦線で値がジャンプしていない**こと（中央行の値を横に
   読んで、隣接テクセル差が周囲の 10 倍を超えない）。あれば §2.2 の
   溶接漏れ（症状: 80〜90 度の光で額から顎までの硬い割線）
4. **ミラー検証**: ライトを左右に振り、正面通過で線が連続に切り替わること
5. **圧縮検証**: テクスチャを BC 圧縮にすると縞状破綻が出ること（＝ 16bit が
   実際に効いている証拠）。非圧縮へ戻す
